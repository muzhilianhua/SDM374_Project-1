# V3.3.1 冻结评分与划分协议

本版在三种模型重新训练前固定，评分、划分、P1 数据及模型参数均有 SHA256 记录。
它是与寻优器无关的离线模型评估，使用已有实测标签，不运行仿真，不生成虚构标签。
原 V3.2 和初始实验版保留，不能跨协议混合排名。

## 一、数据与划分

原始 2048 条数据不改动，校验原始 CSV 的固定 SHA256。
每组外层任务使用 1638 条训练、410 条测试，训练与测试不重叠，并覆盖原始全部 ID。
每组确保测试最优值低于训练最优值。

| 类型 | 冻结规则 | 数量 |
|---|---|---:|
| 隐藏优秀点 | 强制将全局最好的 5、10、20 个点放入测试，再按 SHA256 排序补足 410 条；种子 3301、3302 | 6 |
| 局部区域 | 分别以全局真实排名 1、3、5 的点为中心，强制隐藏全局前 5，再按原始 21 维欧氏距离从近到远补足 410 条 | 3 |

具体 ID 在 `split_manifest.json`，各任务规模、突破空间及低值数量在 `split_summary.csv`。
每组外层训练集内部另有 3 个固定验证折，种子 3303；外层测试不进入任何内部折。
当前模型方案固定参数，不启用内部调参。

9 组任务均包含全局最优点 p01969，不是 9 次独立测试。局部区域任务同时使用标签和几何位置，
是有针对性的压力测试，不是纯粹的无标签空间划分；强制优秀点可能在中心邻域之外。
区域任务的测试集两两 Jaccard 重叠率约为 0.329、0.499、0.364。

## 二、主评估评分：总分 100

每个外层模型对完整测试集预测，按 `(predicted_mean, candidate_id)` 升序确定预测最低点。
精确预测平分时按 ID 升序，不使用近似平分阈值，不使用优化器或模型不确定性。

设 T 为外层训练集真实最优值，O 为测试集真实最优值，A 为预测最低点的真实值。
固定误差尺度 e=5，固定低值阈值 c=132.80。

| 分项 | 最高分 | 公式 |
|---|---:|---|
| 突破识别 | 35 | `35 × max(0, (T−A)/(T−O))` |
| 真实低值准确性 | 30 | `30 / (1 + MAE真实低值 / 5)`，对真实 R≤132.80 的测试样本计算 |
| 预测低值准确性 | 30 | `30 / (1 + MAE预测低值 / 5)`，对预测 R≤132.80 的测试样本计算 |
| P1 专项准确性 | 5 | `5 / (1 + abs(P1预测−119.71206678869203) / 5)` |

突破识别只对实际超过训练最优的结果给分；低于训练最优水平的失败记 0 分，原始损失继续报告。
误差为 5 时，准确性分项得一半分；尺度与权重不根据本次成绩修改。
真实低值区与预测低值区可以重叠：分别检查真正好点的预测和模型报出低值的可信程度。

没有预测低值样本时，该准确性分项为 0，MAE 记 null，不能以空集取得满分。
真实低值区为空、T≤O、缺失或多余测试记录、重复 ID、非有限预测均报错，不静默丢弃任务。
每组必须有且只有 410 个测试预测及 1 个 P1 预测；9 组共 3699 行。

每组先计算四项分数，再汇总：

```text
总分 = 0.5 × 6 组隐藏优秀点任务的平均总分
     + 0.5 × 3 组局部区域任务的平均总分
```

先逐组换算分数再平均，不把全体样本混在一起算一次 MAE，也不先平均误差再换算分数。
同样的汇总方式用于分项与诊断，避免任务数较多的一类自动获得更大权重。

## 三、P1 的两个使用阶段

P1 权重来自 `SUBMISSION_READY/01_FIRST_REAL_TEST/weights.json`，真实值为
119.71206678869203。记录中的载荷哈希以原始 LF 字节为准，Windows CRLF 检出先统一为 LF
再校验；源码来源记录同时保留当前工作副本的实际字节哈希。原始文件不改写。

**主评估：** P1 不参与外层训练和内部训练，但每组额外预测一次，贡献 5 分专项分。
同一个点的 9 次预测不能解释成 9 个独立实测案例，它是已研究过的失败案例而非独立最终测试。

**反馈对照：** 每组原训练数据加入 P1，再从头训练，原 410 条测试数据保持不变。
P1 自身不再计分，此阶段总分上限为 95；已知训练最优 T 更新为包含 P1 后的最优值。
因此两阶段的总分不能直接相减解释成改进，也不能混排；应对比同组测试的真实推荐值、
regret、真实低值 MAE 和强制隐藏优秀点 MAE。

## 四、runze 原前三名的重训定义

原始排名来自 `20261025-204551-artifact-review-v32`。
保留历史低值裁剪与加权策略，固定发布记录中的模态参数，不在新外层测试上重新选参：

| 方案 | 保留训练样本 | 固定参数 | seed |
|---|---|---|---:|
| low90 加权 XGBoost | 按训练真实 R 排序保留最低 floor(0.9n)；原允许训练集最低 floor(0.2n) 权重 3，其余 1 | 600 棵树，深度 3，学习率 0.1，subsample 0.9，hist | 20261024 |
| low80 HistGB | 保留最低 floor(0.8n)，统一权重 | 600 次，15 叶，学习率 0.05，L2=0 | 20263024 |
| low60 HistGB | 保留最低 floor(0.6n)，统一权重 | 600 次，15 叶，学习率 0.1，L2=0 | 20263025 |

训练输入按 candidate_id 排序，标签平分稳定排序；反馈阶段 P1 追加在训练输入末尾。
裁剪和权重只根据该次允许训练的标签计算，不能读取测试标签。
训练环境沿用项目锁定的 numpy 1.24.4、sklearn 1.2.2、XGBoost 3.2.0 等版本。
该版本与原作者历史环境不同，且未重建历史每折的 RMSE 调参，因此是前三种谱系的固定参数重训，
不能声称精确复现历史 74.72/74.50/74.21 分。

研究插件经 registry 构建，仅在本研究入口注册。预测接口的 std 为零占位，**不代表真实不确定性**，
不用于评分或风险寻优。每次保存完整模型和实际保留训练 ID，便于检查训练边界。

另为每种方案保存“全部允许数据提供给训练流程”的最终拟合模型，仍保留该谱系的裁剪策略；
其训练内表现不进入外层成绩。主阶段提供 2048 条，反馈阶段提供 2049 条，实际拟合量见记录。

## 五、运行与输出

```powershell
uv sync --locked --group gui
uv run --locked python analysis/v33_protocol/release_v1/protocol.py validate
uv run --locked python analysis/v33_protocol/release_v1/study.py --recipe runze_low60_histgb --output analysis/v33_protocol/release_v1/results/new-run-low60
```

三个 recipe 名分别为 `runze_low90_xgb`、`runze_low80_histgb`、`runze_low60_histgb`。
每次必须新建输出目录。设置 OMP、OPENBLAS、MKL 线程数为 1。
本机中文路径的 editable 导入异常，训练时明确将 PYTHONPATH 指向本仓库 `src`，并启用 PYTHONUTF8=1；
未修改源码查找逻辑或锁文件。本地环境工具在忽略的 `.tools/`，虚拟环境在 `.venv/`。

每个运行目录保存主阶段和反馈阶段的逐点预测、任务分数、模型、实际训练 ID、最终拟合模型、
软件版本、Git 状态、完整源码及配置哈希。当前未配置 Git 提交身份，运行源码尚未提交，
已如实记录未提交状态与内容哈希，不作为 clean-commit 证据。

`CHECKSUMS.json` 锁定评分实现、方案和冻结数据。`protocol.py freeze` 拒绝覆盖已有版本；
后续设计变更应另建版本，不能看完结果后修改本版标准。

## 六、报告与限制

除主分外，报告真实最优点预测排名、低估偏差、低值样本数、虚假突破、最差任务，
以及强制隐藏优秀点的独立 MAE，避免其表现被补充样本掩盖。

结果见 [delivery/REPORT.md](delivery/REPORT.md)。本次只比较三种固定方案，所有外层任务重复使用
已知数据，不能给出独立显著性结论，不能证明连续寻优的新权重必然 R<115。
总分中的阈值和两类低值区域重叠仍可能产生激励偏差，应结合诊断阅读，不在本次看分后改权重。
