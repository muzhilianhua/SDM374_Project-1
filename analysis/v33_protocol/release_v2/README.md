# V3.3.2：压力测试与低值邻域支持测试

本版执行用户批准的修改：允许优秀样本参与部分训练，补充插值导向的低值测试。
V3.3.1 与 V3.2 完整保留。全部新划分、评分规则与模型参数在新模型训练前冻结。

## 1. 为什么修改

V3.3.1 的 9 组任务全部隐藏全局前 5 个点，只考察没有见过这些优秀样本时的表现。
实际最终训练可以使用这些数据，因此补充“学过部分优秀点，再预测其他优秀点”的场景。

没有见过一个样本不等于外推，附近有训练样本也不保证严格插值。本版将新任务命名为
**低值轮换、邻域支持测试**，并额外检查凸包包含关系，避免混淆几何概念。

## 2. 冻结划分

只使用原始 2048 条实测数据。每组 1638 条训练、410 条测试，不生成新权重或新标签。

| 类型 | 数量 | 定义 | 总分权重 |
|---|---:|---|---:|
| 隐藏优秀点 | 6 | 沿用 V3.3.1：分别强制隐藏前 5、10、20，各用两个固定种子补足测试集 | 25% |
| 局部区域留出 | 3 | 沿用 V3.3.1：围绕真实排名 1、3、5 的点留出邻域，强制隐藏前 5 | 25% |
| 低值轮换、邻域支持 | 5 | 全局前 20 点按真实排名轮转，每组 4 个测试、其余 16 个强制训练；为隐藏点保留邻近训练样本 | 50% |

新增任务的具体规则：

1. 按 `(真实 R, candidate_id)` 排序取前 20 点。
2. 第 k 组隐藏排名 `k,k+5,k+10,k+15`，其余 16 个优秀点固定在训练集。
3. 对每个隐藏优秀点，从本组未被强制隐藏的已有点中，选择原始 21 维欧氏距离最近者，固定在训练集。
4. 排除上述强制训练点，从剩余原始记录中按 SHA256 固定顺序补足测试集至 410 条。
5. 剩余全部作为训练集，冻结其内部三折；当前使用固定参数，不进行新调参。

因此，在新增 5 组中：**前 20 点各测试一次、训练四次；每组前 5 点有 4 个参与训练、1 个测试。**
前 5 点在保留的 9 组压力测试中仍然隐藏。两种条件并存，没有把所有外推考验取消。
低值支持类占 50%，原两类压力任务合计 50%，是本次预先声明的平衡选择，并非根据成绩优化。

具体 ID 见 `split_manifest.json`，样本数量及训练/测试最优值见 `split_summary.csv`。
新增任务种子 3320，内部三折种子 3303，原压力划分完全不变。

## 3. 评分：维持 35/30/30/5，按任务条件解释最优点识别

每组取完整测试集中预测 R 最低的点；预测完全相同时按 ID 升序。
设其真实值为 A，测试集真实最优为 O，训练集真实最优为 T。

### 最优点识别：35 分

- **压力测试：** `35 × max(0, (T−A)/(T−O))`，仍要求测试集中确有突破机会 T>O。
- **低值邻域支持测试：** `35 / (1 + (A−O)/5)`。

新增任务可能已在训练集中包含全局最优，不要求测试点打败训练最优。
识别出测试最优得 35 分；选中点比测试最优差 5，则得 17.5 分。
这种任务中没有突破训练最优不构成失败，只考察对测试优秀点的识别。

### 准确性和 P1：保持原规则

| 分项 | 满分 | 公式与范围 |
|---|---:|---|
| 真实低值准确 | 30 | `30/(1+MAE/5)`；真实 R≤132.80 |
| 预测低值准确 | 30 | `30/(1+MAE/5)`；预测 R≤132.80；空集为 0 分 |
| P1 专项 | 5 | `5/(1+abs(预测−119.71206678869203)/5)`；主阶段不使用 P1 训练 |

每组先计算四项分数，再取类内均分：

```text
总分 = 25% × 隐藏优秀点类平均分
     + 25% × 区域留出类平均分
     + 50% × 低值轮换邻域支持类平均分
```

真实低值为空、输入缺失/重复/多余或预测非有限均报错，不静默丢弃任务。
14 组每组 410 条测试预测及 1 条 P1 预测，共 5754 行。

P1 反馈对照仍将 P1 加入各组训练、测试不变，P1 自身不再计分，上限 95。
反馈后的 T 更新为包含 P1 的已知最优；主阶段与反馈阶段总分不直接混排。
另报告强制隐藏优秀点的独立 MAE、真实最优排名和实际突破等诊断。

## 4. “插值”的实际覆盖

`geometry.py` 用线性规划检查每个强制隐藏优秀点能否由允许训练权重的非负凸组合表示。
重建误差不超过 1e-7 才记为凸包内；它是诊断，不作为本次换样本或调分的依据。

- 20 个轮换优秀测试点中，**9 个位于允许训练集凸包内**。
- 所有 20 个保留的邻近点均在允许训练集中。
- 模型裁剪之后，三个模型仍各有 9/20 个点位于实际拟合样本凸包内。
- low60 保留了 19/20 个指定邻近点，low80 和 XGBoost 各保留 20/20 个。

因此该类是插值导向、包含严格插值样本的测试，不能声称 20 个点全部成为严格插值。
训练裁剪可能丢弃邻近支持，实际情况单独记录，不通过更改评分或划分掩盖。
详见 `geometry_diagnostics.csv`、`retained_geometry.csv`、`retained_geometry_summary.json`。

## 5. 训练与复现

复用 V3.3.1 的三种固定方案，保留裁剪、加权、模态参数与种子，不重新调参。
研究插件通过 registry 构建，std 的零值只是未使用的占位，不代表不确定性为零。

```powershell
uv sync --locked --group gui
uv run --locked python analysis/v33_protocol/release_v2/protocol.py validate
uv run --locked python analysis/v33_protocol/release_v2/study.py --recipe runze_low60_histgb --output analysis/v33_protocol/release_v2/results/new-low60
```

另外两个 recipe 为 `runze_low80_histgb`、`runze_low90_xgb`；输出目录必须新建。
中文路径下本机运行需设置 `PYTHONUTF8=1`、`PYTHONPATH=本仓库/src`，并将 OMP、OPENBLAS、MKL 线程设为 1。
本地 Python 3.11 与依赖环境沿用原 uv.lock。每次运行保留源码哈希、Git 状态、版本、训练 ID 和模型。
当前源码未提交，结果如实记录，不宣称 clean-commit 证据。

## 6. 结果与边界

三种方案均完成 14 组主评估和 14 组反馈评估，总计 84 次任务拟合及 6 次最终拟合。
结果见 [delivery/REPORT.md](delivery/REPORT.md)。新旧评分任务权重不同，不能把分数变化当作模型变好。

新增轮换仍是已有数据内部的条件测试，14 组训练数据高度重叠；不能推断独立显著性，
不能保证连续寻优生成的新权重达到真实 R<115。此前冻结版本不覆盖；设计再变动需另建版本。
