# 在线阶段任务说明

[`team.md`](team.md) 第 3 节的任务表只写一句话和负责人；本文件说明每项任务的**原因、内容、作用和产出物**，供领取任务和评审 PR 时对照。
任务 ID 与 `team.md` 一致；任务表变更时，同一个 PR 也要更新本文件。

## 全局目标与主线

在线阶段的成绩：超过我们离线结果（离线最好 R = 115.68，提交 2，见 decisions.md Findings）得 8%，组间排名得 5%（取最好的一次调用）；另有代码、创新点和报告分。
规则：提交一份冻结、可复现的脚本，在课程电脑上**最多顺序调用评估器 20 次，每次最多 50 组权重**；
第 1 次调用前只能使用 2048 条训练数据；每次调用取批内最低 R，成绩取所有调用中的最低值；
同一点不得重复评估（决策 19、20、22）。

时间节点（详见 `team.md` 第 2 节）：11 月 12 日第 9 次课前完成大部分代码工作并同步进度；11 月 14–15 日开始准备 PPT、

## 3.2 在线运行框架

### T06 评估器接口
- **原因**：同一个在线主循环要对接三种"评估器"：正式运行用真实 `solver.exe`，回放用表格查值或半合成真值，测试用快速替身。如果每处都各写一遍调用代码，正式运行和回放就无法保证跑的是同一套逻辑。
- **内容**：定义一个评估器接口（输入最多 50 组权重，返回 R 列表），实现以下几个版本：
  - 真实 solver：stdin JSON、解析 `{"R": [...]}`、退出码 2 时报错并保留 stderr、超时按 50 组约 5 分钟设置、正式模式下绝不删除 `usage.count`。
  - 表格查值版。
  - 半合成真值版。
- **作用**：T08、T17、T19 和测试共用一个入口，保证回放结论能迁移到正式运行。
- **产出物**：`src/sdm/` 中的评估器模块和单元测试；`docs/interfaces.md` 中新增的接口说明。

### T07 调用日志
- **原因**：20 次调用是唯一能计分的数据，必须完整、不可篡改地记录下来。续跑（T08）、并入训练数据（T08、T13）、画曲线（T26）都要读这份日志。
- **内容**：定义 `online_log.csv` 的字段（调用号、批内序号、21 个权重、R、来源策略或分组、run id、时间），实现只追加写入；读取时校验字段和调用号连续。
- **作用**：作为在线阶段唯一的事实来源，保证结果可追溯，失败后可以恢复。
- **产出物**：日志格式说明（写入 `docs/interfaces.md`），读写函数及测试。

### T08 在线主程序
- **原因**：比赛交付的就是这个程序。它要把"提议 → 检查 → 调用 → 记录 → 重训"自动串起来，任何一步出错都可能浪费额度或违规。
- **内容**：实现 `sdm online -c <配置>`（名称可定），每次调用依次：
  1. 用 2048 行 + 已有日志重建 `X, y`，训练代理模型。
  2. 由策略提出最多 50 个点。
  3. 提交前检查：单纯形约束、与训练行和已发送点去重、批大小、剩余额度。
  4. 调用评估器，写日志。
  5. 进入下一次调用。

  程序中断后从日志续跑，已发送的批不再重发。
- **作用**：把模型和策略组装成可交付的脚本；回放器（T17）也复用这个循环。
- **产出物**：CLI 命令、在线配置模板 `experiments/online-*.toml`、端到端测试（使用 T06 的替身评估器）。

### T09 跨机器确定性
- **原因**：决策 22 要求在课程电脑上重跑时发出完全相同的批次。但 xgboost 等库在不同 CPU 和操作系统上可能有微小差异（Known issues），一个点的差别会让后续所有批次都不同。
- **内容**：用同一配置和替身评估器在两台机器上运行，逐位比较每一批点；若有差异，就固定线程数、换用确定性实现或调整模型，直到一致。
- **作用**：保证本地演练的结果就是正式运行的结果，避免冻结后才发现结果不可复现。
- **产出物**：比较脚本与结果记录（两台机器的环境信息和比较结论），必要的配置或代码修改。

### T10 课程电脑运行包
- **原因**：课程电脑是 Python 3.14，而 numpy 1.24.4 没有 3.12 以上的安装包；是否有 uv 未知；路径若含中文，editable 安装会找不到 `sdm`（今天在本机已复现）。不解决这些问题，程序在课程电脑上根本无法启动。
- **内容**：根据 T03 的结论选择方案，例如 uv 安装 Python 3.11、离线打包虚拟环境或可执行文件，或去掉 editable 依赖；写一条命令的启动脚本和操作步骤。
- **作用**：让正式运行和 T21 的演练能在课程电脑上一次成功。
- **产出物**：启动脚本（如 `run_online.ps1`）、运行说明文档、在干净机器上验证通过的记录。

### T11 GUI 在线控制台（P2）
- **原因**：演练和正式运行时，人需要直观地看到额度、检查结果和进展；目前这些只能读日志。
- **内容**：在工作台新增页面，显示已用 / 20 次额度、每批的提交前检查结果、最优值曲线。按决策 8，所有计算仍通过 CLI 完成。
- **作用**：减少操作失误，答辩时可以现场展示。
- **产出物**：`app/` 中的新页面和 GUI 测试。

## 3.3 代理模型

### T12 在线代理模型选择
- **原因**：离线阶段按 v3.2 分数排出的模型，不一定最适合在线循环。在线时数据逐批增加，需要每次快速重训，并且要在搜索区域内预测准确。离线结果表明，boosted trees 在被搜索的区域过于乐观（提交 1 预测 107–111，实测 119.7）。
- **内容**：在回放器上比较 GP、local-gp、boosted trees、stack 等候选模型，看逐次最优值、预测与实测误差和重训耗时，选定策略使用的模型及其参数。
- **作用**：决定在线策略的"眼睛"，直接影响成绩。
- **产出物**：比较结果（带 run id），推荐的模型配置，记入 decisions.md。

### T13 在线重训与误差报告
- **原因**：每次调用后都有 50 个新的真实点，这是检验和修正模型的最好机会；同时需要量化模型在新区域预测得准不准。
- **内容**：主程序每次重训时，记录上一批的预测与实测误差（平均误差、最低点误差、std 覆盖率），写入运行记录或日志。
- **作用**：发现模型系统性乐观或悲观时可以修正；也为报告提供"预测与实测"的证据。
- **产出物**：重训与误差记录的代码和测试，演练中每次调用的误差表。

### T14 不确定度校准
- **原因**：策略的探索部分依赖 `std` 判断哪里值得去试。如果 `std` 太窄，就只会围着已知点打转；太宽，则会浪费点数。
- **内容**：让所选模型的 `std_coverage` 落在 0.55–0.80 之间；可选对信赖域附近的样本加权，提高局部精度。
- **作用**：让探索和利用的分配有依据。
- **产出物**：校准后的模型或参数，`sdm evaluate` 的 run id 与覆盖率指标。

## 3.4 提议策略

### T15 批量提议策略
- **原因**：成绩只看批内最低值，所以每批 50 个点的目标是"让其中一个点尽可能低"，而不是平均值低。第 1 批只能依据训练数据，要格外谨慎设计。
- **内容**：实现一个策略插件：在模型最看好的区域密集利用，同时分出一部分点做探索；批内互不重复，也不与训练行或已发送点重复；第 1 批与后续各批可以采用不同比例。比例等参数留作配置，由 T18 决定。
- **作用**：这是决定成绩的核心算法。
- **产出物**：`src/sdm/optimizers/` 中的新插件、配置、契约测试和专项测试。

### T16 信赖域半径自适应
- **原因**：固定的搜索半径要么太保守，要么容易外推。离线结果显示，离数据太远的点实测会明显变差（baseline W\*、提交 1）。
- **内容**：仿照 TuRBO，当前批若刷新最优值就扩大半径，若没有就缩小，并设定上下限。
- **作用**：在 20 次调用内自动平衡大胆与稳妥。
- **产出物**：策略中的半径更新逻辑、参数和测试；在回放中与固定半径的对比。

## 3.5 回放与分析

### T17 离线回放器
- **原因**：正式运行只有一次，而本地用真实 solver 完整跑一遍要约 1.6 小时，每比较一组配置都要跑这么久。所以需要一个快速、可复现的环境，来大规模比较不同模型和策略；用本地结果调参是允许的（决策 27）。
- **内容**：复用 T08 的主循环，把评估器换成以下两种之一：
  - 表格留出池：从 2048 行中留出一部分当"未知"，策略只能从池中选点。
  - 半合成真值：用拟合的模型当真实函数，沿用 `analysis/coupling/` 的方法。

  输出每次调用的最优值曲线，固定种子可复现。
- **作用**：作为 T12、T18 的实验平台，也为报告提供策略对比的主要证据。
- **产出物**：`src/sdm/replay.py`、回放配置、测试，以及曲线和结果文件（带 provenance）。

### T18 策略参数比较与推荐
- **原因**：T15 和 T16 留下的参数（利用 / 探索比例、半径、模型选择）需要用证据来定，而不是凭感觉。
- **内容**：在回放器上做有限规模的参数比较（多个种子、两类真值），报告逐次最优值曲线和最终最低值的分布，给出推荐配置及其理由。
- **作用**：确定冻结时使用的配置。
- **产出物**：比较结果与推荐配置 `experiments/online-*.toml`，记入 decisions.md。

### T19 真实评估器完整演练
- **原因**：回放用的是替身，只有真实 solver 能检验整条链路：耗时、输出格式、额度计数、模型在新区域的真实误差。
- **内容**：本地用真实 `solver.exe` 按冻结前的配置完整跑一次 20 × 50（约 1.6 小时评估时间），对比预测与实测。结果可以用来修改模型、策略和参数（决策 27），但提交的代码不能内嵌本地测得的点或 R 值。
- **作用**：在冻结前发现运行层面的问题，并预估正式成绩。
- **产出物**：演练日志、误差与耗时报告，发现的问题清单。

### T20 机理笔记（P2）
- **原因**：理解权重如何影响 R（楼内比例、楼间可加性、2 号楼低敏感度），可以给模型提供先验，也能丰富报告的分析部分。
- **内容**：基于训练数据和已有的真实点做分析，整理成可以落实到模型或策略的先验。
- **作用**：可能提高模型精度；为报告提供讨论素材。
- **产出物**：`analysis/mechanism/README.md` 及其分析脚本。

## 3.7 报告与答辩

### T23 复现 baseline
- **原因**：报告中所有改进都要相对 baseline 来说明，而 baseline 的数字必须来自我们框架中可复现的运行。
- **内容**：用 `sdm evaluate` 运行 `baseline-v32.toml` 和 `baseline.toml`，记录 run id，并与课程给出的数值核对。
- **作用**：为消融表格和报告提供基准行。
- **产出物**：run id 及其在报告草稿中的引用。

### T24 消融框架
- **原因**：创新分（5%）和报告分（5%）需要说明"哪一部分带来了多少改进"，这需要系统化的对比表，而不是零散的数字。
- **内容**：用 `sdm.catalog` 从运行记录生成"模型 × 特征 × 优化器"的表格；所有图表一条命令即可重建。
- **作用**：让报告中的每个数字可追溯、可重算。
- **产出物**：`analysis/ablation/` 中的脚本和生成的表格与图片。

### T25 报告模板与 Introduction
- **原因**：IEEE 格式且限 4 页，五个人分头写章节，必须先有统一的模板、绘图风格和每人的篇幅预算，否则合并时要大改。
- **内容**：搭建 IEEE LaTeX 模板（每人一个章节文件）和统一的绘图风格模块；给 T27–T31 分配报告篇幅预算；起草 Introduction。
- **作用**：让各人从第一天起就写在同一个框架里，报告统稿（T32）时只需微调。
- **产出物**：`report/` 下可编译的 LaTeX 工程（含各章占位文件）、绘图风格模块、篇幅预算表。

- **原因**：在线阶段最有说服力的证据是 20 次调用的最优值变化，以及模型预测与实测的对比。
