# 武韵扬汇报部分：评估器、模型与策略选择

建议控制在 2 分 30 秒左右，PPT 用 3 页。所有分数都是 R，**越低越好**。

## 第 1 页：黑箱评估器与任务约束（约 50 秒）

页面标题：`评估器与在线优化协议`

页面放这几句话：

- 输入：3 栋楼 × 每栋 7 个控制权重，共 21 个变量；每栋楼权重非负且归一化。
- 评估器返回一周 168 小时用电波动量：
  \[
  R=\sum_{t=2}^{168}|E_t-E_{t-1}|.
  \]
- R 是黑箱输出，不能直接求梯度；正式在线最多 20 次调用，每次最多 50 组权重。
- 第一次调用只能使用 2048 条训练数据，之后只能使用本轮已经测到的 R。
- 最终成绩取所有在线提交点中的最小 R，因此每一批既要利用模型，也必须保留探索点。

讲稿：

“我们的目标不是预测某一个小时的电量，而是让一周总用电曲线的相邻小时变化尽可能小。评估器接收三栋楼的 21 个权重，返回黑箱指标 R，R 越低越好。每栋楼的权重必须是一个合法的 simplex，也就是非负并且和为 1。在线阶段只有 20 次调用、每次最多 50 个点，而且第一轮只能看训练集，后续才能加入自己测出来的结果，所以它更像一个受预算限制的黑箱优化问题。因为最终看的是所有点里的最低 R，我们不能把整个批次都交给一个可能外推错误的模型。”

## 第 2 页：代理模型为什么这样选（约 45 秒）

页面标题：`代理模型选择：结构特征 + 局部不确定性`

页面放这几句话：

- 原始 21 维权重改成每栋楼的结构特征：
  - degradation / (degradation + ramping)；
  - degradation + ramping 的总占比；
  - 5 个次要目标相对主目标的比例。
- 代理模型：全训练集 Ridge 趋势 + incumbent 附近的局部 GP 残差。
- 训练集交叉验证支持按楼 additive 分解：R² 约 0.846，普通全交互模型约 0.844。
- 选择依据：数据量只有 2048 行、变量在 simplex 上、在线样本少；局部 GP 可以给出不确定性，Ridge 提供离开训练点后的趋势。

讲稿：

“模型选择上我们没有直接使用高容量模型去拟合 21 个原始权重。训练数据只有 2048 行，而权重存在每栋楼归一化约束，所以我们先使用每栋楼的比例和相对占比特征。代理模型由两部分组成：Ridge 学习全局趋势，局部 GP 学习当前最优点附近的残差，同时给出预测标准差。训练集检查显示，把三栋楼作为近似 additive 的三个 block，交叉验证 R² 约为 0.846，和完整交互模型的 0.844 接近。因此我们把每栋楼分开搜索，减少模型在小数据上的外推风险。”

## 第 3 页：策略选择与结果（约 55 秒）

页面标题：`从 V1 到 V4：把预算用在有效搜索上`

建议放一张小表：

| 策略 | 主要变化 | 3 个种子平均最终 R |
|---|---|---:|
| V1 | 基础 block descent | 106.89 |
| V2 | 加入训练数据导出的 shift bias | 106.52 |
| V4 | null-step、后期 coordinate scan、自适应配额、去重 | **105.59** |
| V5 | V4 + 大量 vertex probe / lane | 106.26 |
| V6 | V4 + stalled building lane / spawn | 106.86 |

可在表下补充：`V4 seed 7 = 103.275；V4 seed 2026 = 108.049；seed 11 = 105.440`。

讲稿：

“策略上我们从 block descent 开始，每个候选主要只改变一栋楼，这样可以估计单楼权重块的增益，再把不同楼的有效 block 组合到下一轮。V2 的 shift bias 来自训练集中的 Spearman 关系。V4 的关键改进不是盲目增加模型复杂度，而是利用在线结果：过滤已经证明处于平台区的 null step；第 9 轮之后做坐标级扫描；根据各类候选的命中率自适应分配 model、random、fine 和 scan 配额；并且保证不重复训练点和历史提交点。真实 solver 回放中，V4 的三种子平均最终 R 是 105.59，优于 V1、V2、V5 和 V6，所以最终冻结 V4。V5 和 V6 虽然搜索了更多 block 形态，但在 1000 个在线点的预算下分散了主下降路径，结果反而变差。”

## 收尾（约 15 秒）

“因此我们的选择逻辑是：用结构化代理模型负责导航，用 additive block descent 负责可解释的局部搜索，再用少量随机和坐标扫描保护探索能力。当前证据支持 V4，但 seed 之间仍有约 103 到 108 的波动，所以我们把它作为有限预算下的稳定候选，而不是声称已经找到全局最优。”

## 老师可能追问

### 为什么不用 Transformer？

“Transformer 更适合有足够样本和序列结构的任务。这里输入是 21 维静态权重，只有 2048 个训练点，在线也只有 1000 个反馈点。现有回放中 GP / Ridge 的局部不确定性更直接服务于候选筛选，Transformer 没有显示出足够的验证优势。”

### 102.10 是不是我们的正式结果？

“不是。102.10 来自大量离线 solver 探索，只用于理解地形；正式在线策略在第一轮不能读取那些点，因此不能把它写入策略或当作正式成绩。V4 的正式研究证据是 20×50 的合规回放。”

### 为什么 R=105 比 R=118 好？

“R 是波动量，目标是最小化，所以数值越低越好。分数如果使用其他映射，需要先确认助教的评分定义；我们这里报告的是 solver 原始 R。”

### 评估器到底返回什么？

“输入是 JSON 中的一组或多组 3×7 权重，返回对应数量的 R。正式 runner 负责合法性检查、去重、顺序调用、日志和断点续跑；策略本身只生成候选。”

## 不要在 PPT 中说的内容

- 不要说已经证明 V4 能从任意种子到 104；已有结果的 seed spread 仍然很大。
- 不要把 solver 逆向结果、102.10 的权重或历史低点写进正式策略说明。
- 不要把 V5/V6 的失败描述成模型完全错误，准确说法是：在 20×50 的预算下，额外换形搜索分散了有效的 V4 descent。
- 助教尚未确认提交包细节时，只介绍“runner 已具备配置冻结、去重、checkpoint 和 synthetic 验证”，不要宣称课程机正式提交已经完成。
