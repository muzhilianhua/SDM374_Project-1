## 3. 任务表（在线阶段，第 8–10 周）

在线阶段的交付物是一份**冻结、可复现的脚本**：在课程电脑上最多顺序调用评估器 20 次，每次最多 50 组权重；
第 1 次调用前只能使用 2048 条训练数据；成绩取所有调用中的最低 R（决策 19、20、22）。下面的任务按工作流分组，
覆盖从运行框架、模型、策略、回放验证到冻结提交和报告的全部工作。每项任务的原因、内容、作用和产出物见
[`online-tasks.md`](online-tasks.md)。

- 状态：`待办` → `进行中` → `待审`（PR 已开）→ `完成`（PR 已合并）；卡住时写 `受阻：<原因>`。
- 工作量（参考）：S ≈ 1、M ≈ 2、L ≈ 4 个单位，只用来估计每人承担的工作，**不换算为分数，也不代表最终贡献分配**。
  表中的工作量是暂定值，需各负责人在评审时确认或提出修改后定稿（见第 4 节）。
- 优先级：P0 = 正式运行或交付必需；P1 = 直接提高成绩或报告质量；P2 = 有余力再做。

### 3.8 验收标准

- 运行框架：中断续跑不会重复调用；提交前检查拒绝任何不合规或重复的点。
- 模型：在 `frozen-v32` 协议上用 run id 证明优于 ridge2，且通过插件契约测试。
- 策略：只提出互不重复的新点；`distance_ratio` ≤ 1.5，否则需要负责回放的成员签字。
- 回放：固定种子可复现，并给出逐次最优值曲线。
- 报告：每个数字和图都标注来源 run id。

## 4. 标准流程

### 查看分工
1. 打开本文件。第 1 节是你负责的路径，第 2 节是时间节点，第 3 节按"负责人"一列查找你的任务。
2. 让编程助手（Claude Code、Codex）干活时，告诉它"我是 <姓名>"，它会读 `AGENTS.md` 和本文件。

### 领取或新增任务
1. 在任务表里新增一行或改写一行：写清任务、负责人、建议工作量和依赖，状态设为 `待办`。
2. 新增任务和工作量调整随 PR 提交，由张子木在合并时确认；工作量有争议的，在 PR 里讨论定下。
3. 两人合作的任务，在"负责人"一列写明分配比例，例如 `胡馨澜 60% / 艾子齐 40%`，默认平分。

### 更新进度
1. 开始做时，把状态改为 `进行中`。可以单独提交这一行，也可以随第一个 PR 一起改。
2. 交付时在**同一个 PR** 里把状态改为 `待审`，在"证据"一列填 PR 号和 run id；PR 描述写明任务 ID（见 PR 模板）。
3. PR 合并后，由合并者把状态改为 `完成`。没有合并记录的任务不算完成。
4. 卡住超过两天时，改为 `受阻：<原因>`，并在群里告诉依赖你的人。
5. 每个时间节点前（11 月 12 日、11 月 14–15 日、11 月 19 日），张子木对照 PR 核对一遍任务表，在下面的记录里写一行结论。
